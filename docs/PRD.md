# AI 공감 다이어리 PRD

- 상태: **승인됨(2026-11-19)**. 열린 질문 답변을 반영한 확정본
- 기술 결정은 해당 개발 담당과 협의할 사항으로 표시한다.
- "(PM 추천안으로 확정)"은 사용자가 PM 추천안대로 하라고 정한 항목이다.

## 1. 배경과 문제 정의

- 배경: 하루를 짧게 돌아보는 습관은 도움이 되지만, 긴 일기는 부담이라 이어가기 어렵다. 한 줄만 써도 마음을 알아주는 답이 돌아오면 쓰는 일이 가벼워진다.
- 문제: (1) 일기를 쓰고도 아무 반응이 없어 혼자 말하는 느낌이 든다. (2) 힘든 날의 기록이 쌓여도 감정의 흐름을 돌아보기 어렵다. (3) 아주 힘든 순간의 글을 저장만 하면 도움이 필요한 사람을 놓친다.
- 해결 방향: 오늘 있었던 일을 한 줄로 쓰면 AI가 감정을 분류하고 공감 메시지를 돌려준다. 위기로 보이는 표현이 있으면 공감과 함께 전문 상담 연락처를 안내한다.

## 2. 목표와 성공 기준

### 목표

1. 구글 계정으로 로그인해 자기 일기만 쓰고 볼 수 있다.
2. 한 줄 일기를 쓰면 감정, 강도, 공감 메시지를 바로 받는다.
3. 위기 표현은 AI 상태와 관계없이 놓치지 않고 상담 연락처로 이어 준다.
4. 따뜻하고 편안한 일기장 화면으로 매일 열고 싶게 한다.

### 성공 기준 (측정 가능한 지표)

| 번호 | 지표 | 목표값 | 확인 방법 | 단계 |
|---|---|---|---|---|
| S1 | 로그인 → 일기 쓰기 → 결과 → 기록 보기 전체 흐름 | 실제 구글 계정·DB·AI로 끝까지 성공 | 수동 확인 | 3, 5 |
| S2 | 다른 계정의 일기 접근 | 목록·상세·삭제 모두 0건 노출(상세·삭제는 404) | 계정 2개 시험, 자동 테스트 | 2, 4 |
| S3 | 위기 시험 문장(준비한 위기 표현 목록) 안내 비율 | 100% (AI 실패 상황 포함) | QA 시험 문장 세트 | 4 |
| S4 | 평범한 시험 문장의 위기 오탐 | 평범한 문장 20개 중 2개 이하 (PM 추천안으로 확정) | QA 시험 문장 세트 | 4 |

| S7 | 두 모델 모두 실패 시 일기 보존 | 저장 성공, 일기 유실 0건 | 오류 처리 시험 | 4 |

- 힘든 감정을 쓸 수 있으므로 안전하고 비난하지 않는 말투가 중요하다.

## 5. 범위 밖 항목

이번에 하지 않는다. 원래 요구에 없던 기능이다.

- 구글 외 로그인(이메일, 카카오 등), 회원 탈퇴 전용 화면, 프로필 설정
- 일기 공유, 친구, 댓글, 공개 일기
- 알림·리마인더, 이메일 발송
- 일기 검색, 태그, 사진·음성 첨부, 내보내기
- 감정 통계 그래프, 달력, 연속 작성 일수 같은 기록 보상
- 관리자 화면, 결제, 광고
- 여러 언어 지원(한국어만)
- 의료적 진단·치료 조언. 이 앱은 상담이나 치료를 대신하지 않는다.
- AI 챗봇 형태의 대화(공감 메시지는 일기당 한 번만 돌려준다)
- 네이티브 앱(웹만)

## 6. 화면 목록과 흐름

### 화면 목록

| 화면 | 주소(안) | 내용 | 로그인 필요 | 기능 |
|---|---|---|---|---|
| 로그인 | `/login` | 앱 소개 한 줄, 구글 로그인 버튼, 무료 모델 상시 안내문 | 아니오 | F1, F2 |
| 일기 쓰기 | `/` | 일기 입력(Enter 보내기, Shift+Enter·Alt+Enter 줄바꿈), 남은 글자 수, 보내기 버튼, 상시 안내문, 지난 기록 링크, 로그아웃 | 예 | F1, F2 |
| 결과 | 쓰기 화면 안 또는 `/entries/[id]` | 감정·강도, 공감 메시지, 위기 시 연락처 카드, 분석 실패 시 안내 | 예 | F3, F5 |
| 지난 기록 | `/entries` | 날짜별 목록, 감정 표시, 더 보기 | 예 | F4, F6 |
| 기록 상세 | `/entries/[id]` | 일기 내용, 감정·강도, 공감 메시지, 위기 시 연락처 카드, 삭제 | 예 | F4, F5, F7 |

결과를 별도 화면(주소)으로 할지 쓰기 화면 안에 보일지는 frontend-developer와 협의한다. 로딩·오류·빈 기록 상태 화면은 모든 화면에 포함한다.

### 흐름

```
로그인 화면 --구글 로그인--> 일기 쓰기 화면 --보내기--> (분석 중 기다림 표시)
   --> 결과(감정·강도·공감 메시지, 위기면 상담 연락처 카드)
   --> "지난 기록 보기" --> 기록 목록 --> 기록 상세(삭제 가능)
```

- 로그인하지 않고 쓰기·기록 화면에 가면 로그인 화면으로 보낸다.
- 분석 중 새로고침해도 일기는 이미 저장되어 있어야 한다. (저장 순서는 backend-developer와 협의)
- 분석에 실패하면 결과 자리에 실패 안내가 나오고, 일기는 기록에 남는다.

### 7.2 감정 분류 목록과 강도 표현 (Q4 결정)

AI가 아래 8개 중 정확히 하나를 고른다.

| 감정 | 설명 |
|---|---|
| 기쁨 | 즐겁고 뿌듯함 |
| 설렘 | 기대되고 두근거림 |
| 평온 | 편안하고 차분함, 무난한 하루 |
| 슬픔 | 서럽고 아쉬움 |
| 외로움 | 혼자라고 느낌, 그리움 |
| 불안 | 걱정되고 초조함 |
| 화남 | 짜증, 억울함 |
| 지침 | 피곤하고 무기력함 |

- 강도는 5단계(사용자 요청으로 변경, 2026-11-19): 1 매우 약함, 2 약함, 3 보통, 4 강함, 5 매우 강함. 화면에는 말과 점 5개 채우기로 보여준다. 색은 frontend-developer가 정하되 이름 글자도 함께 보인다.
- 한 일기에 감정은 하나만 표시한다. 여러 감정이 섞여도 가장 두드러진 하나를 고른다.
- 위기 여부(`crisis`)는 감정과 별개의 값이다.

## 8. 위기 대응 정책

원칙: 위기 안내는 AI에만 맡기지 않는다. 서버의 키워드 검사와 AI 판단 중 하나라도 위기로 보면 안내한다. 연락처는 AI가 만들지 않고 코드에 고정된 내용을 보여준다.

### 8.1 위기로 볼 표현의 기준

아래 중 하나라도 해당하면 위기로 본다. 구체적인 키워드 목록은 backend-developer가 이 기준으로 별도 파일에 만들고 QA가 시험 문장으로 점검한다.

| 범주 | 예시 표현(대표 예. 전체 목록 아님) |
|---|---|
| 죽음·극단적 선택 의사 | "죽고 싶다", "죽어버리고 싶다", "자살", "목숨을 끊고", "극단적인 선택" |
| 계획·수단·시기 언급 | "죽으려고 약을 모았다", "오늘 밤 끝낼 거야" |
| 자해 | "손목을 긋", "자해", "스스로 해치" |
| 사라지고 싶다는 소망 | "사라지고 싶다", "없어지고 싶다", "깨어나지 않았으면" |
| 존재 부정·짐 | "내가 없는 게 낫다", "살 이유가 없다", "살기 싫다" |
| 돌려 말하기 | "다 끝내고 싶다", "모든 걸 놓고 싶다" |

- 판단은 안전 쪽으로 한다. 놓치는 것보다 과하게 안내하는 쪽을 택한다. 단, 오탐이 많으면 안내가 무뎌지므로 오탐 목표(S4)를 둔다.
- 관용적 과장 표현("배고파 죽겠다", "웃겨 죽는 줄")은 키워드 검사에서 제외한다(Q9, PM 추천안으로 확정). 이런 문장도 AI 판단이 위기로 보면 위기가 된다.
- 과거형·남의 이야기("친구가 죽고 싶다고 했다")도 일단 위기로 안내한다. 안전 우선이다.
- 위기 여부는 일기와 함께 저장한다(`crisis`).

### 8.2 안내 방식

- AI 공감 메시지(가능하면)와 함께 상담 연락처 카드를 결과 화면과 기록 상세 화면에 보여준다.
- AI가 실패했을 때는 고정 공감 문구와 연락처 카드를 보여준다.
- 위기일 때는 감정이 "기쁨" 같은 값으로 나와도 연락처 카드는 반드시 나온다.
- 위기 안내에서는 훈계·진단·"괜찮아질 거예요" 식의 가벼운 위로를 피한다.

## 9. AI 모델 정책

| 순서 | 모델 | 언제 쓰나 |
|---|---|---|
| 1순위 | `nvidia/nemotron-3-ultra-550b-a55b:free` | 항상 먼저 호출 |
| 2순위 | `nvidia/nemotron-3.5-super-vl:free` | 1순위가 시간 초과(모델당 20초)·오류 응답·빈 응답·형식 오류일 때 |

- 호출은 OpenRouter, 키는 환경 변수 `OPENROUTER_API_KEY`, 서버 코드에서만 읽는다.
- 두 모델 이름이 OpenRouter 목록에 실제로 있는지는 2단계 시작 때 ai-integration-specialist가 확인해 보고한다. 이름이 없으면 PRD를 고쳐야 하므로 사용자에게 알린다.
- 두 모델 모두 실패하면(Q5 결정): 일기는 저장하고 "분석 실패" 상태로 표시한다. 위기 키워드 검사는 그대로 적용한다. 다시 분석은 나중에(F8).
- 무료 모델은 제공사가 입력을 기록하거나 학습에 쓸 수 있다. 사용자에게는 F2의 상시 안내문으로 알린다(Q3 결정). 무료 모델의 데이터 정책 설정은 ai-integration-specialist가 확인한다.
- 무료 모델은 속도 제한·일시 중단이 있을 수 있다. 서비스 수준을 약속하지 않는다.
- 분석 결과 형식(`analyzeDiary(text) → { emotion, intensity, message, crisis, model }`)과 API는 1단계에서 확정한다.

### 사용자 준비물과 알릴 시점

- 구글 OAuth 값(`AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`)과 `AUTH_SECRET`은 `.env`에 아직 없다(Q1 결정). 사용자가 나중에 직접 만든다.
- 개발 중 이 값이 필요해지는 시점, 곧 로그인을 실제로 시험하는 때(1단계의 로그인 확인 항목, 3단계 통합)에 개발 담당이 사용자에게 알리고 요청한다. 그 전까지는 로그인 외 부분을 가짜 데이터로 진행한다.
- 값은 사용자가 `.env`에 직접 추가한다. 문서·답변에는 변수 이름만 쓴다.
